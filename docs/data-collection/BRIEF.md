# 카드피커 카드 데이터 수집 브리프

너는 한국 신용/체크카드의 **기본 혜택 구조**를 조사해서 아래 JSON 형식으로 정리하는 수집가다.
결과는 사람이 검수하기 전 초안이다. 정확하지 않은 값은 추측하지 말고 memo에 "확인 필요"라고 적어라.

## 도구
- WebSearch로 카드 목록·공식 페이지 주소를 찾고, WebFetch로 페이지를 읽는다.
- 카드사 공식 페이지 읽힘 여부 (2026-08-16 시험):
  - 잘 읽힘: 신한카드(shinhancard.com), KB국민카드(m.kbcard.com 모바일 페이지가 잘 읽힘)
  - 절반: 삼성카드(카드명·혜택 종류는 나오나 세부 수치는 접힌 부분)
  - 안 읽힘: 현대카드, 카드고릴라 (자바스크립트 렌더링)
  - 정리 사이트 뱅크샐러드(banksalad.com/product/cards/...)는 잘 읽힘 → **참고용으로만**. 공식 페이지가 안 읽힐 때 참고하고, memo에 "출처: 뱅크샐러드 참고, 공식 확인 필요"라고 적어라.
- officialUrl은 반드시 **카드사 공식 도메인의 https 주소**여야 한다 (뱅크샐러드/카드고릴라 주소 금지). 정확한 상세 페이지를 못 찾으면 카드사 홈 도메인(예: https://www.hyundaicard.com)이라도 넣고 memo에 적어라.

## 대상
- 현재 **판매 중(신규 발급 가능)** 카드만. 단종·발급중단은 넣지 않는다.
- 이벤트성·기간 한정 혜택(신규 발급 캐시백, 이달의 이벤트 등)은 **제외**. 카드의 상시 기본 혜택만.
- 개인 신용카드 위주. 체크카드는 혜택이 뚜렷한 것만 소수.
- 각 카드사의 대표·인기 카드부터. 태그가 골고루 덮이게 고른다.

## 태그 15개 (정확히 이 문자열만 사용) — 2026-08-20 카페·편의점/통신비·OTT 분리, 2026-08-21 마트·장보기 신설
`마일리지` · `모든 가맹점` · `주유` · `카페` · `편의점` · `마트·장보기` · `온라인 쇼핑` · `배달·외식` · `대중교통·택시` · `통신비` · `OTT·구독` · `병의원·약국` · `해외 결제` · `학원·교육` · `관리비·공과금`

태그 매핑 지침:
- 마일리지: 항공 마일 적립(대한항공/아시아나/기타 항공). rate는 "1,000원당 1마일 = 0.1" (1,500원당 1마일 = 0.067, 1,000원당 1.5마일 = 0.15). monthlyCap은 **월 최대 적립 마일**(마일 단위), 없으면 null.
- 모든 가맹점: 어디서 써도 적용되는 적립/할인. 이 경우 `universal`도 채우고, benefits에도 tag `모든 가맹점` 항목을 **반드시** 하나 넣는다(둘 다 같은 rate/cap). 전 가맹점 마일리지 카드는 universal(type mileage) + benefits에 `마일리지`와 `모든 가맹점` 둘 다.
- 주유: 주유소 할인/적립(정유사 선택형 포함). LPG·충전 제외 여부는 note에.
- 카페: 스타벅스/이디야/투썸 등 카페·커피전문점, 베이커리 포함 가능(note에 명시).
- 편의점: GS25/CU/세븐일레븐/이마트24.
- **카페와 편의점을 한 혜택으로 묶어 주는 카드**(통합 한도): 두 태그로 각각 한 줄씩 넣고 같은 `capGroup`(예: "cafecvs")으로 묶어라. 각 줄의 monthlyCap은 통합 한도 값 그대로.
- 마트·장보기: 대형마트(이마트/홈플러스/롯데마트/하나로마트)·창고형(트레이더스/코스트코)·슈퍼마켓(SSM: 이마트에브리데이/홈플러스익스프레스/롯데슈퍼) **오프라인** 장보기. 편의점(이마트24 등)은 `편의점`, 온라인 장보기 앱(컬리/쿠팡 등)은 `온라인 쇼핑`으로.
- 온라인 쇼핑: 쿠팡/네이버/G마켓/11번가/SSG 등 온라인몰, 온라인 간편결제, 온라인 장보기(컬리/오아시스 등).
- **마트와 온라인몰(또는 다른 영역)을 한 통합 한도로 묶어 주는 카드**: 두 태그 각 한 줄 + 같은 `capGroup`(예: "shop").
- 배달·외식: 배달의민족/요기요/쿠팡이츠, 음식점·패스트푸드.
- 대중교통·택시: 버스/지하철, 택시.
- 통신비: 이동통신(SKT/KT/LGU+/알뜰폰) 요금 자동이체, 인터넷·유선.
- OTT·구독: 넷플릭스/유튜브프리미엄/디즈니/티빙 등 OTT, 멜론 등 구독·멤버십 정기결제.
- **통신과 OTT를 한 혜택으로 묶어 주는 카드**(통합 한도): 두 태그 각 한 줄 + 같은 `capGroup`(예: "telott").
- 병의원·약국: 병원·의원·약국·동물병원.
- 해외 결제: 해외 가맹점 적립/할인, 해외이용 수수료 면제(수수료 면제는 rate 0, note에 적고 stars 1).
- 학원·교육: 학원, 학습지, 유치원·어린이집, 등록금.
- 관리비·공과금: 아파트관리비, 전기/가스/수도, 4대보험, 국세/지방세.
- 위 15개 밖의 혜택(영화, 놀이공원, 백화점 단독, 골프, 라운지, 바우처 등)은 benefits에 넣지 말고 memo에만 한 줄로.
- **같은 카드 안에서 같은 tag를 두 번 쓰지 마라** (스키마가 거부함). 한 태그에 여러 세부 혜택이 있으면 대표 하나로 합치고 note에 나머지를 적어라.

## ★ 등급 · 복잡도 기준 (STAR_GUIDE)
- ★3: 할인/적립 7% 이상이면서 월 한도 15,000원 이상, 또는 마일리지 1,000원당 1.5마일 이상
- ★2: 할인/적립 3~7% 또는 월 한도 5,000원 초과~15,000원, 마일리지 1,000원당 1마일 안팎
- ★1: 그 외 (5% 미만이면서 한도 5,000원 이하 등)
- "모든 가맹점"(범용 적립/할인) 벤핏의 ★은 적립률로: 0.5% 미만 ★1, 0.5%~1% 미만 ★2, 1% 이상 ★3 (마일리지 범용은 마일리지 기준)
- 복잡도 1: 전 가맹점 단일 적립/할인, 실적 없거나 낮음, 제외 항목 거의 없음
- 복잡도 2: 영역 혜택 2~3개, 실적 조건 1단계
- 복잡도 3: 선택형 팩, 실적 구간별 한도, 제외 항목 많음

## 카드 1장 JSON 형식 (필드 이름·타입 정확히. 다른 필드 추가 금지 — 스키마가 거부함)
```json
{
  "id": "shinhan-deep-oil",              // 소문자 영문/숫자/하이픈. 카드사-카드명
  "name": "신한카드 Deep Oil",            // 카드사 공식 표기
  "issuer": "신한카드",                   // 신한카드/KB국민카드/삼성카드/현대카드/롯데카드/우리카드/하나카드/NH농협카드/BC카드/카카오뱅크/토스뱅크 등
  "kind": "credit",                        // "credit" | "check"
  "annualFee": 10000,                      // 원, 정수. 브랜드별로 다르면 가장 낮은 값(국내전용 우선)
  "minSpend": 300000,                      // 전월 실적 원, 정수. 없으면 0
  "benefits": [
    { "tag": "주유", "type": "discount", "rate": 10, "monthlyCap": 15000, "stars": 3, "note": "정유사 1곳 선택, LPG 제외" }
  ],
  "universal": null,                       // 또는 { "type": "points", "rate": 1, "monthlyCap": null }
  "complexity": 2,
  "officialUrl": "https://www.shinhancard.com/...",
  "lastChecked": "2026-08-18",
  "status": "active",
  "memo": "AI 수집, 검수 전. 출처: 공식 페이지. 롯데시네마 5천원 할인은 태그 밖."
}
```
- `type`: "discount"(할인/청구할인/캐시백) | "points"(포인트 적립) | "mileage"
- `rate`: 퍼센트 숫자. 정액 할인(예: 건당 1,000원 할인)이면 대략적인 %로 환산하지 말고 rate는 대표 % 없으면 0, note에 정액 내용을 적고 monthlyCap에 월 한도 원.
- `capGroup`(선택): 한도를 공유하는 혜택들엔 같은 문자열, 예: "shared" — 그 벤핏들의 monthlyCap엔 공유 한도 금액을 그대로 적는다.
- memo는 항상 "AI 수집, 검수 전. 출처: ..."로 시작.

## 이미 들어있는 카드 (중복 금지)
전체 목록은 같은 폴더의 `existing-ids.txt` (id | 이름). 반드시 읽고 이름·id 둘 다 겹치지 않게 하라.

## 출력
- 지정된 파일 경로에 **JSON 배열만** 저장 (주석 없이, 위 예시의 `//` 주석은 실제 파일에 넣지 마라).
- 마지막 답변은 15줄 이내: 저장한 카드 수, 카드명 목록, 못 읽어서 참고 사이트를 쓴 카드, 확인 필요한 항목.

## 추가 지침 (3차 수집부터)
- WebSearch는 에이전트당 약 200회 한도가 있다. 카드 1장당 검색 3~4회 안에서 끝내고, 못 찾으면 그 카드는 건너뛰어라. 목표 장수보다 **정확한 카드**가 우선.
- 이미 수집된 카드 목록은 existing-ids.txt(docs/data-collection/)에 있다. id뿐 아니라 **카드 이름**도 겹치지 않게 확인하라 (예: "KB국민 스카이패스카드"가 있으면 같은 카드를 다시 넣지 않는다).
- 공식 페이지 읽힘 여부 (경험): 신한·KB(m.kbcard)·롯데(lottecard 상세)·BC(m.bccard)·케이뱅크 잘 읽힘 / 삼성 절반 / 현대·하나·NH·우리 대부분 JS라 뱅크샐러드 참고 → memo에 명시.
- 뱅크샐러드 카드 페이지 주소는 `https://www.banksalad.com/product/cards/CARD######` 형식이며 WebSearch로 "뱅크샐러드 <카드명>"을 검색하면 찾힌다.
- 체크카드는 kind "check", 연회비 0이면 annualFee 0.

## 추가 지침 (4차 수집, 2026-08-18)
- **월 한도(monthlyCap)는 최우선으로 찾아라.** 이 사이트는 한도를 그대로 "연 최대 혜택"으로 계산한다. 한도가 null이면 월 1만 원으로 가정 계산되어 카드가 과소평가된다. 공식 페이지에 없으면 뱅크샐러드·카드고릴라에서 찾고, 실적 구간별로 다르면 **가장 낮은 실적 구간의 한도**를 monthlyCap에 넣고 note에 구간별 한도를 적어라. 정말 한도가 없으면 note에 "한도 없음(공식 확인)"이라고 적어라.
- **한도를 여러 혜택이 나눠 쓰면 `capGroup`을 반드시 넣어라** (같은 그룹 = 같은 문자열, monthlyCap엔 공유 한도 금액을 각각 동일하게). 두 개 이상의 풀이 있으면 "a", "b"처럼 다른 문자열.
- **note는 사용자가 화면에서 그대로 읽는 문장이다.** "확인 필요", "미확인", "출처" 같은 내부 메모는 note에 쓰지 말고 **memo**에 써라. note는 혜택 조건만 짧게 (예: "정유사 1곳 선택, 리터당 할인 아님").
- lastChecked는 "2026-08-18". memo는 "AI 수집(2026-08-18), 검수 전. 출처: …"로 시작.
- 프리미엄 카드: 연회비 5만~30만 원대이면서 **초대·자산 조건 없이 누구나 신청 가능한** 카드만. 바우처·라운지·호텔 등 태그 밖 혜택은 memo에 한 줄로만. 태그 안 혜택(마일리지·모든 가맹점·해외 결제 등)이 하나도 없으면 넣지 마라(추천에 뜰 수 없다).
- 이미 들어있는 카드는 `existing-ids.txt`(id | 이름) 참고. 같은 카드의 다른 에디션/버전이면 이름에 에디션을 정확히 붙여라.
- **구간 정액 혜택은 요율로 환산하라.** "10만 원마다 5천 원" 같은 구조는 rate 5(%)로 적고 monthlyCap에 월 최대 금액을 넣어라. rate 0(정액)은 "건당 N원 1회"처럼 이용금액과 무관한 경우에만. (rate 0이면 사용액 상한이 안 걸려 과대평가된다.)
- **실적 구간이 있으면 `tiers`로 적어라.** 기본 rate/monthlyCap은 카드 minSpend부터 적용되는 **최저 구간** 값. 그 위 구간은 `"tiers": [{ "minSpend": 700000, "monthlyCap": 30000 }, { "minSpend": 1000000, "rate": 12, "monthlyCap": 50000 }]` 처럼 minSpend 오름차순으로(카드 minSpend보다 커야 함). rate는 기본과 다를 때만. 통합 한도(capGroup) 혜택들은 tiers의 minSpend·monthlyCap이 서로 같아야 한다. `universal`에 구간이 있으면 universal.tiers와 '모든 가맹점' 벤핏의 tiers를 같게. note에는 구간을 다시 나열하지 마라(화면이 구조적으로 보여준다). 상위 구간의 monthlyCap은 공식적으로 '한도 없음'일 때만 null로 적는다(모르면 구간을 넣지 마라). 통합 한도(capGroup) 혜택의 구간 한도는 null일 수 없다.
