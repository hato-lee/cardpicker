# 12개 태그 판정 교차 검토

검토하면서 원본 행 파일과 `src/engine/benefit.ts`, `src/data/cards.json`을 직접 확인했다. 확인한 것: 태그별 active 행 수, `applyCapGroups` 실제 동작, `rate===0` 처리, `nh-zgm-discount`·`kb-need-pay`·`shinhan-edu`·`hana-travelog-check`의 실제 인코딩, 관리비·공과금 27행 전수 재분류, 배달·외식 69행 키워드 대조.

## ② 판정을 뒤집은 것

### 관리비·공과금: `split` → `note-fix`

담당 에이전트의 갈래 분류(관리비만 8 / 전기가스만 5 / 둘 다 14)는 내가 27행을 다시 읽어 **그대로 맞다고 확인했다.** (나) 기준도 인정한다 — 주거형태로 갈리는 건 취향이 아니라 상태라서 "지하철만 탄다"보다 오히려 더 단단하다. 뒤집은 이유는 셋이다.

**(1) (다) 계산에 단종 카드가 섞였다 — 이게 결정적이다.**
에이전트는 22행/19행 → "계산 미반영 2행 빼면 20/18"이라고 했다. 그런데 `recommend.test.ts:34-37`이 확인해 주듯 `discontinued`·`excluded` 카드는 추천에서 아예 빠진다. 관리비·공과금 27행 중 **5행이 discontinued**다(`kb-tantandaero-allshopping`, `hana-1q-daily`, `woori-loca-apt-platinum`, `samsung-card4-v4`, `hana-1q-shopping-plus`).

| | 에이전트 집계 | 실제(active) | 계산에 실제로 잡히는 것 |
|---|---|---|---|
| 아파트관리비 | 22 | **18** | **17** |
| 전기·가스 | 19 | **16** | **14** |

기준선 20장을 **양쪽 다** 못 넘긴다. 참고로 선례는 쪼갠 뒤 대중교통 68 / 택시 49(active)였고, 배달·외식은 42/33이 된다. 17/14는 급이 다르다.

**(2) "쪼개서 되찾는 혜택" 2건이 둘 다 단종 카드다.**
근거로 든 `hana-1q-daily`(전기·가스 영역 복원)와 `hana-1q-shopping-plus`(관리비·4대보험 5,000원 복원)는 **둘 다 status=discontinued**다. 화면에 안 뜨는 카드다. 선례에서 split을 정당화했던 "되찾은 혜택 표"에 해당하는 실익이 이 태그에는 0이다.

**(3) 피해 사례 4건 중 3건이 split과 무관하게 고쳐진다.**
`nh-zgm-discount`(cap 20,000 → note는 "영역당 5천"), `lotte-loca-365`(5,000+5,000을 10,000 한 줄로), `woori-loca-apt-platinum`(33%와 6%를 12.31%로 뭉갬 — 게다가 단종). 전부 **값 수정**이다. 갈래 어긋남이 진짜 원인인 건 `shinhan-edu`(rate 100, 관리비 전용) / `shinhan-mr-life`(전기·가스 전용) 두 장뿐이고, `shinhan-edu`는 애초에 "당월 교육비 결제가 있어야만" 나오는 조건부 혜택을 무조건으로 인코딩한 별개 오류를 함께 안고 있다.

**대신 할 것:** ① `nh-zgm-discount` 관리비 행 20,000 → 5,000 ② `lotte-loca-365` 10,000 → 5,000 ③ `shinhan-edu` rate 100의 조건부 성격 반영(하향 또는 issueNote) ④ 그 뒤 다시 재어 보고, 그때도 오염이 남으면 재검토. **일관성 근거:** 학원·교육 에이전트는 (다)를 엄격히 적용해 학습지 16장에서 split을 기각했다. 같은 잣대를 관리비에 대면 기각이 맞다.

### 라벨만 바로잡는 것 (판정 뒤집기는 아님)

- **해외 결제**: `note-fix`라고 했지만 본인 리포트의 핵심은 note가 아니라 `rate 0` 규약 변경이다. 태그 판정은 `keep`, 별건으로 **엔진/규약 이슈 1순위**로 올린다. 태그 자체는 어긋남 0%로 12개 중 가장 건강하다.
- **병의원·약국 / OTT·구독 / 카페**: `note-fix`인데 실제 권고에 **행 삭제**가 들어 있다(동물병원 3, OTT 1, 카페 2). "설명 보완"이 아니라 "오태깅 제거"라 성격이 다르다 — 아래 ③-3에서 묶어 다룬다.

## ③ 12개를 통틀어 본 구조적 문제

**1. 진짜 어긋남 축은 '하위 업종'이 아니라 '지정 브랜드·체인·자격 전속'이다. 그래서 태그로는 못 고친다.**
12개 중 11개가 같은 그림이었다 — 카페는 스타벅스가 118행 중 113행, 편의점은 GS25·CU가 69행 중 67행, 마트는 top5가 전부 단일 체인 전용(트레이더스·하나로·롯데·이마트), 주유는 1~2개 정유사 전용이 40%, 온라인 쇼핑은 단일몰 전용 8행, 통신비는 알뜰폰 명시 제외 32행, 학원은 브랜드 전속 학습지 3장, 해외는 국내 PG 경유 제외. **이건 갈래가 아니라 카드 하나하나의 자격 조건**이라 태그를 2배로 늘려도 안 없어진다. 필요한 건 새 태그가 아니라 카드마다 붙는 **조건 배지/필터 필드**(예: `restrictedTo: "스타벅스"`, `"트레이더스"`, `"SK텔레콤"`, `"알뜰폰 제외"`)다. 태그 분리 논의보다 이쪽이 사용자 체감이 훨씬 크다.

**2. 엔진이 모르는 조건이 4종류이고, 왜곡 방향이 항상 '과대'다.**
① 건당 최소 결제금액(카페 29행·통신비 16행·배달 다수 — 커피 한 잔 4,700원인데 "건당 1만원 이상"이면 실제 0원) ② 결제수단 전속(`kb-need-pay`는 8개 업종 태그에 15%로 들어가 있는데 실제 조건은 "KB Pay로 결제 시"다 — 실물카드만 쓰면 전부 0원) ③ 유료 멤버십·통신사 전속(코스트코·트레이더스 클럽·SK텔레콤·네이버플러스) ④ 수수료 면제(rate 0). 전부 "요율은 맞는데 자격이 없다" 유형이다. 태그를 아무리 잘 나눠도 이 4종은 그대로 남는다.

**3. note가 스스로 "이 태그 대상 아님"이라 적어 놓은 행이 태그에 붙어 점수를 받는 게 최소 8행.**
`kb-easy-auto-titanium`(카페 — "커피전문점은 대상이 아님"), `hana-wonder2-free`(카페 — "커피전문점 미포함"), `shinhan-starfield`·`nh-zgm-discount`·`ibk-i-all`(병의원 — 동물병원 전용), `shinhan-deep-on-platinum-plus`(OTT — "일반 OTT 미포함"), `kb-kpass`·`kb-kpass-check`(배달·외식 — "배달앱·일반 음식점 제외"). **가장 싸고 가장 확실한 수정**이고, ENCODING-RULES §7 "태그 밖 혜택은 benefits 금지" 규약 위반이라 논쟁의 여지도 없다.

**4. capGroup 진단을 3명이 같은 방향으로 잘못했다 — 이대로 고치면 오히려 망가진다.**
편의점·병의원·마트 에이전트가 "태그를 1개만 고르면 `applyCapGroups`가 축소를 안 걸어 통합한도 전액이 그 태그 몫이 된다"를 **엔진 버그**로 지목했다. 코드는 확인했고(`benefit.ts:96` `if (groupRows.length < 2) continue`) 동작은 그대로다. 하지만 **순수 공유한도라면 그게 맞는 계산**이다 — 신세계 통합 5만원을 편의점에서만 다 써도 5만원을 받는 게 사실이니까. 진짜 문제는 **"영역별 개별한도 + 별도 통합한도"인데 개별한도 자리에 통합한도를 넣은 인코딩**이다. `nh-zgm-discount`가 교과서 사례다 — 6개 행이 전부 `cap 20000, capGroup "life"`인데 note는 "영역당 월 5천원"이다. 태그 1개 선택 시 4배, 2개 선택 시 2배. **엔진을 건드리면 정상 카드가 죄다 과소평가된다. 고칠 건 데이터다.**

**5. `nh-zgm-discount` 한 장이 6개 태그를 동시에 오염시키고 있다.** 관리비·통신비·온라인 쇼핑·병의원·OTT·마트 담당 4명이 각자 독립적으로 같은 카드를 지목했다. 한 줄씩 6줄 고치면 6개 태그가 동시에 좋아진다 — 이 조사에서 나온 최고 가성비 수정이다.

**6. BRIEF.md 태그 정의가 실제 데이터와 안 맞는 게 3건.** 병의원·약국의 "동물병원"(오분류 3건의 직접 원인), 학원·교육의 "등록금"(대상 행 0개, 명시 제외 8행), 관리비·공과금의 "수도·국세·지방세"(대상 행 0개, 명시 제외 5~7행). **데이터만 고치고 지침을 두면 다음 수집에서 그대로 재발한다.**

**7. 12명의 집계 기준이 통일돼 있지 않았다.** 어떤 에이전트는 discontinued를 빼고 세고 어떤 에이전트는 넣고 셌다(그래서 관리비 판정이 뒤집혔다). 다음 라운드에는 "**(다) 기준은 status=active 카드로만 센다**"를 명시해야 한다.

## ④ 하토님께 권하는 다음 행동

### 지금 할 것 하나 — "값이 틀린 것"만 고치기 (코드 변경 0, cards.json만)

태그를 쪼개는 것보다 **먼저** 해야 하고, 훨씬 싸고, 효과가 6~8개 태그에 동시에 퍼진다.

1. `nh-zgm-discount` — 생활할인 6개 행 `monthlyCap` 20,000 → **5,000** (통합 2만원은 memo로). 6개 태그 동시 개선.
2. **오태깅 행 8개 삭제** (위 ③-3 목록). note에 "대상 아님"이라고 카드사가 직접 써 놓은 행들이다.
3. `lotte-loca-365` 10,000 → 5,000, `hyundai-costco-reward-edition2` `monthlyCap` null → 실제 한도, `kb-coupang-wow`·`hana-wonder2-free-plus`·`shinhan-lottemart-maxx` capGroup 누락 보완.
4. **BRIEF.md 태그 정의 3줄 수정** (동물병원 / 등록금 / 수도·국세). 재발 방지용.

반나절이면 끝나고, 엔진·UI·테스트를 하나도 안 건드린다.

### 그다음 결정 하나 — 해외 결제 `rate 0` 규약을 어떻게 할지

이건 제가 정할 수 없고 하토님이 정하실 문제다. 지금 규약("수수료 면제는 rate 0")대로면 **하나 트래블로그 체크가 해외 결제 태그에서 111장 중 93위, KB 위시 트래블은 100위에 연 -25,000원**으로 나온다. 한국에서 해외여행용으로 제일 많이 쓰는 카드들이 "손해 보는 카드"로 찍히는 거라, 사용자가 결과를 보자마자 사이트를 못 믿게 되는 종류의 오답이다.

- **A안(권장)**: 해외 결제 태그에 한해 수수료 면제를 요율로 환산(보수적으로 1.2%). 담당 에이전트 시뮬레이션 기준 트래블로그 체크 93→23위, 솔트래블 체크 94→24위로 정상화된다.
- **B안**: 규약 유지하되 해외 결제 태그 결과 화면에 "수수료 면제형 카드는 요율 0으로 표시됩니다" 안내를 붙인다.

**지금 하지 마실 것:** 배달·외식 분리는 근거가 충분하지만(80%, 42장/33장) **줄 복제 13건 + capGroup 재설계 + 원문 재확인 17건 + UI·테스트 수정**이 붙는 작업이다. 위 값 수정을 먼저 끝내고 그다음 별도 라운드로 잡으시는 게 좋다. 나머지 10개 태그는 **쪼개지 마시라** — 조사 결과 현행 유지가 맞았다.
