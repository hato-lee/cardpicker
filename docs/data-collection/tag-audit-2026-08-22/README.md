# 태그 16개 내부 분열도 조사 (2026-08-22)

`대중교통·택시`를 쪼갠 뒤(`../tag-split-2026-08-21/`) **"다른 태그도 한쪽만 대상인 행이 많은가"** 를 조사했다.
태그 12개(마일리지·모든 가맹점·대중교통·택시 제외)에 에이전트를 하나씩 붙여 1,134행 중 738행을 전수 분류하고,
13번째 에이전트가 판정 12개를 교차 검토했다.

- `tag-scope-audit.json` — 태그별 갈래 정의·행 분류·판정·피해 사례
- `cross-review.md` — 교차 검토(우선순위, 뒤집은 판정, 구조적 문제)
- `value-fix-verification.json` — 조사에서 지목된 값 오류 후보 8건의 원문 재확인 결과

## 결론: 쪼갤 만한 태그는 `배달·외식` 하나뿐

| 태그 | 한쪽만 대상 | 판정 |
|---|---|---|
| **배달·외식** | **80%** | **분리 권장** (배달앱 vs 음식점) |
| 통신비 | 71% | 유지 |
| 온라인 쇼핑 | 59% | 유지 |
| 카페 | 52% | 유지 |
| 마트·장보기 | 50% | 유지 |
| 관리비·공과금 | 48% | 유지 (split → 뒤집힘) |
| 학원·교육 | 41% | 유지 |

**비율만으로 판단하면 틀린다.** 통신비는 71%인데도 인터넷·유선만 대상인 행이 **0개**다 — 갈라진 게 아니라
이동통신 쪽으로 쏠린 것이라 쪼개면 진부분집합만 생긴다. 카페도 118행 중 113행이 스타벅스를 포함해
어긋남이 **한 방향뿐**이다. 대중교통·택시처럼 **양쪽이 서로 남남**이어야 분리할 값어치가 있다.

판정 기준 4가지: (가) 한쪽만 대상인 행 30% 이상 (나) 사용자가 그 구분으로 카드를 고르는 게 자연스러운가
(다) 쪼갠 뒤 **active 카드**가 각 20장 이상 (라) note 수정만으로 충분한가.
관리비·공과금이 `split`에서 뒤집힌 것은 (다)를 셀 때 단종 카드가 섞여 있었기 때문이다(22/19 → 실제 17/14).

## 진짜 문제는 태그가 아니라 '자격 조건'이었다

12개 중 11개가 같은 그림이었다 — 어긋남의 축이 하위 업종이 아니라 **지정 브랜드·체인·자격 전속**이다.
카페는 스타벅스 113/118, 편의점은 GS25·CU 67/69, 마트 상위 5장이 전부 단일 체인 전용, 통신비는 알뜰폰 명시 제외 32행.
태그를 두 배로 늘려도 안 없어진다. 필요한 건 새 태그가 아니라 **카드마다 붙는 조건 표시**다.

엔진이 모르는 조건 4종(왜곡 방향은 항상 '과대'):
① 건당 최소 결제금액(카페 29행 — 커피 한 잔 4,700원인데 "건당 1만원 이상") ② 결제수단 전속(`kb-need-pay`는 8개 태그에 15%인데 실제 조건은 "KB Pay로 결제 시")
③ 유료 멤버십·통신사 전속(코스트코·트레이더스·SKT·네이버플러스) ④ 수수료 면제(rate 0 → 계산상 0원)

## 이 조사에서 새로 드러난 것

- **B-5 (신규)**: capGroup이 걸리면 `requiredSpend`가 안 줄어 이중으로 깎인다 — 태그를 하나 더 고르면
  카드 가치가 절반이 되는 역전이 생긴다. 엔진 한 줄 수정으로 고쳐지지만 capGroup 카드 전체 숫자가 바뀐다.
- **BRIEF 태그 정의 3건이 실제 데이터와 안 맞았다** — 관리비·공과금의 "수도·국세·지방세"(대상 행 0개),
  학원·교육의 "등록금"(대상 2·제외 6), 병의원·약국의 "동물병원"(전용 행 3개). 데이터만 고치면 다음 수집에서 재발하므로 지침을 고쳤다.
- 집계 기준 통일 필요: **(다) 기준은 `status: active` 카드로만 센다.**
