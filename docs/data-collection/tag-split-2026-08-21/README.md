# '대중교통·택시' 태그 분리 (2026-08-21)

하나였던 `대중교통·택시` 태그를 **`대중교통`(시내·마을·광역버스 + 지하철 + 후불교통 GTX·공항철도)** 과
**`택시`(택시업종 + 카카오T·UT·타다 호출앱)** 로 쪼갰다. 태그는 15개 → 16개.

## 왜

기존 태그가 붙은 **99개 행을 전수 분류하니 절반 넘게 한쪽만 대상이었다.**

| 판정 | 행 수 |
|---|---|
| 버스·지하철만 (택시 제외) | 45 |
| 택시만 (버스·지하철 제외) | 22 |
| 둘 다 | 32 |

한 태그로 묶여 있으면 지하철만 타는 사람에게 "택시만 50% 적립"이, 택시를 원하는 사람에게
"택시 제외" K-패스 카드가 점수를 받는다. K-패스가 버스·지하철만 환급하고 택시는 대상이 아닌 것도
같은 이유다 — 이제 K-패스 스위치는 `대중교통`만 자동으로 켠다.

## 분류 근거

`classification.json` — 99행 전부에 대해 scope·요율·한도·근거(출처 인용)·확신도.
에이전트 13개가 카드사 공식 페이지·카드고릴라 상품안내 원문·상품설명서 PDF를 대조했다.
확신도 high 97 / medium 2 (medium 2건은 아래 '남은 불확실').

## 태그를 쪼개서 되찾은 혜택

한 태그에 한 행만 둘 수 있어 **note에 글로만 적혀 있던 반대편 혜택**을 이제 행으로 살렸다
(OPEN-ISSUES B-2 문제의 부분 해소).

| 카드 | 되찾은 것 |
|---|---|
| `shinhan-b-big` | 버스·지하철 후불교통 정액할인(일 200~600원) → 대중교통 6.5%/4,000원 |
| `ibk-kpass` | 일반교통 5%(택시) → 택시 5%/500원 |
| `mg-kpass-check` | 생활혜택 10%의 택시분 → 택시 10%, 생활 통합한도(capGroup `life`) |
| `kakaobank-friends-check`·`kakaobank-kpass-friends-check` | 택시업종 3만원↑ 1,000원 → 택시 3.3% |

요율이 수단별로 달랐는데 한 줄로 뭉개져 있던 것도 각자 제 요율을 갖게 됐다:
`shinhan-tmoney-paygo`(버스·지하철 30% / 티머니GO 택시 20%), `bc-baro-onoff`(한도 4,000 / 5,000),
`hana-wonder-daily`(영역별 개별 한도표).

## 한도 처리 규칙

- 둘 다 대상이고 **한 한도를 나눠 쓰면** 줄을 복제하고 같은 `capGroup`으로 묶는다 (26장).
  안 묶으면 한도가 두 배로 계산된다. 새로 만든 그룹 10개, 기존 그룹에 합류 13장.
- **수단별 개별 한도가 원문에 있으면** 묶지 않고 각자의 한도를 쓴다 (6장).
- **한도가 없는 혜택**(`kb-gaon`·`kb-all-point`·`samsung-traders-club`)은 나눠 쓸 상한 자체가 없어
  묶지 않는다. 스키마상 `capGroup`은 `monthlyCap`이 null이면 못 쓰기도 한다.

이 규칙이 깨지지 않게 `src/data/cards.test.ts`에 회귀 테스트를 뒀다.

## 남은 불확실

- `hana-wonder-daily` 대중교통: 공식 페이지 **상단 요약은 3%, 하단 상세표는 10%**로 어긋난다.
  상세표(+영역별 4,000원 한도 구조)와 형제 카드 LIFE를 근거로 10%를 유지했으나 3%일 가능성이 남는다.
- `shinhan-b-big` 대중교통: "일 N원"은 하루 승차 횟수를 가정해야 % 환산이 된다.
  하루 왕복 2회(3,100원)·월 20일 승차로 잡았다 — 둘 다 보수 쪽 가정이지만 가정은 가정이다.
- `ibk-kpass` 택시: 명목 한도 5,000원인데 "월 2회" 제한이 실질을 결정해 500원으로 낮춰 잡았다.
  실제 택시비가 기본요금보다 비싸면 실질 한도는 이보다 올라간다.
- `kakaobank-*` 택시·대중교통: 2026-02~2027-01 프로모션이라 2027년 2월에 조건 재확인이 필요하다.
- `shinhan-deep-oil`: memo는 '단종(신규발급 중단)'으로 적혀 있는데 `status`는 `active`다 (태그와 무관, 별도 확인 필요).
