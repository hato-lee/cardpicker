# 카드피커 혜택 note 문구 정리 브리프 (2026-08-18)

카드 데이터의 `benefits[].note`는 **사용자 화면에 그대로 보이는 문장**이다("전체 혜택" 목록: `주유 10% 할인 · 월 최대 1.5만 원 (note)`).
그런데 수집 과정에서 남긴 내부 표현 — "확인 필요", "미확인", "미기재", "추정", "(뱅크샐러드 확인)", "(공식 확인)", "출처: …", "태그 밖이라 미기재", "정정" 같은 말 — 이 note에 남아 있다. 이걸 **사용자용 문장으로 다시 쓰는** 일이다. 웹 검색은 하지 않는다. 사실을 새로 만들지 않는다.

## 입력
지정된 `todo-X.json`: `[{ id, tag, note }]` 배열 (현재 note).

## 규칙
1. **사실은 남기고, 메타 정보는 뺀다.** 남길 것: 대상 가맹점·업종, 조건(실적, 건당 금액, 요일, 횟수), 한도 숫자, 다른 혜택과의 통합 관계, 제외 항목. 뺄 것: 확인 여부·출처·수집 사정("태그 밖이라 미기재", "태그 중복 제한으로", "정정", "…로 채택"), 내부 필드명(rate=, tiers, capGroup 등), 다른 항목을 가리키는 "(… 항목 참고)".
2. **모르는 값은 그냥 안 쓴다.** "월 한도 확인 필요" → 삭제(화면이 `한도 없음`/`월 최대 N원`을 별도로 표시하니 note에서 반복할 필요 없음). "정확한 구간 조건 확인 필요" → 삭제. "OTT 포함 여부 확인 필요" → 삭제(포함 여부를 모르면 언급 안 함).
3. "한도 없음(공식 확인)" → 화면이 이미 `한도 없음`을 표시하므로 note에서 그 부분은 빼고 나머지만 남긴다. 나머지가 없으면 note를 빈 문자열이 아니라 **삭제**(patch에서 `"note": null`로 표기 — 아래 참고).
4. 어조: 짧은 명사구/한 문장, 존댓말 어미 없이(기존 note 스타일: "정유사 1곳 선택, LPG 제외"). 숫자는 "월 3만 원", "1,500원당 1마일"처럼 읽기 쉽게. 100자 안팎이 좋다.
5. note에서 뺀 불확실성·출처 정보는 버리지 말고 카드 memo에 옮긴다: `memoAppend`에 " 노트정리(2026-08-18): <태그>: <뺀 내용 요약>" 형태로 한 카드에 한 줄로 합쳐 적는다.
6. 이미 깨끗한 note는 건드리지 않아도 된다(그 카드는 패치에서 빼거나 note 없이 memoAppend만).

## 출력: 지정된 `notes-X.json`에 **패치 배열만** 저장 (JSON, 주석 없음). 카드 1장 = 패치 1개.
```json
[
  { "id": "shinhan-mr-life",
    "benefits": [ { "tag": "주유", "set": { "note": "리터당 60원 할인, 일 1회, 월 이용액 30만 원까지 적용" } } ],
    "memoAppend": " 노트정리(2026-08-18): 주유: 월 할인 원화 한도 미확인(이용액 기준 30만 원만 알려짐)." },
  { "id": "lotte-loca-platinum-discount",
    "benefits": [ { "tag": "모든 가맹점", "set": { "note": null } } ],
    "memoAppend": " 노트정리(2026-08-18): 모든 가맹점: '한도 없음(공식 확인)'은 화면 표기와 중복이라 note 삭제." }
]
```
- `set.note`가 `null`이면 note를 지우라는 뜻(적용 스크립트가 처리한다).
- `set`에는 note만 넣어라(다른 필드 변경 금지).

## 마지막 답변 (5줄 이내)
고친 note 수 / 지운 note 수 / 판단이 애매했던 것 1~2개.
