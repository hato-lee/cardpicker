# '배달·외식' 태그 분리 (2026-08-22)

하나였던 `배달·외식`을 **`배달앱`**(배달의민족·요기요·쿠팡이츠·땡겨요 등 배달 앱 결제)과
**`외식`**(음식점 업종 오프라인 현장 결제)으로 쪼갰다. 태그는 16개 → 17개.

`../tag-audit-2026-08-22/`에서 태그 12개를 전수 조사한 결과 **배달·외식이 한쪽만 대상인 행 80%로 가장 심하게
갈려 있어** 유일하게 분리 판정을 받은 태그다. 대중교통·택시(68%)보다도 어긋남이 컸다.

## 분류 결과 (69행 전수, 확신도 전부 high)

| 판정 | 행 수 |
|---|---|
| 배달앱만 | 32 |
| 외식만 | 24 |
| 둘 다 | 13 |

**카드사가 스스로 둘을 별개 영역으로 판다.** 삼성 iD SELECT는 배달앱과 음식점이 택1,
토스뱅크 체크는 배달앱이 '온라인 모드'·음식점이 '음식&음료 모드'로 스위치가 배타적이다.
결제 경로도 갈린다 — 배달앱은 PG·온라인 거래, 음식점은 업종코드 기준 현장 결제다.

**판별의 기본값**: "음식점 업종 N%"처럼 업종코드 기준이면 **외식**이다. 배달앱 결제는 PG·온라인 업종으로 잡혀
별도 명시가 없으면 빠지는 게 통례이고, 실제로 여러 카드의 원문이 그 점을 못박고 있었다
(신한 처음 "배달앱을 통해 이용한 거래는 포인트가 적립되지 않습니다", KB 굿데이 "PG업체를 통한 결제 … 할인대상에서 제외",
KB 가온 "KB국민카드 가맹점 업종코드상 적립대상 가맹점업종으로 등록된 경우에 한하여").

## 태그를 쪼개서 되찾은 혜택

한 태그에 한 행만 둘 수 있어 **note·memo에만 갇혀 있던 혜택**을 행으로 살렸다(OPEN-ISSUES B-2).
앞의 세 장은 해부 기록에 "태그 중복 금지로 미반영"이라고 명시돼 있던 것들이다.

| 카드 | 되찾은 것 |
|---|---|
| `samsung-id-select-on` | 배달앱 5%·월 5,000원 (옵션과 무관한 상시 혜택인데 통째로 빠져 있었다) |
| `kb-you-wish` | 위시 픽 '배달' 팩의 배달앱 5% (capGroup `wishpick` — 팩 택1이라 필수) |
| `kb-my-wesh` | '먹는데 진심' 팩의 배달앱 5% (capGroup `pack`) |
| `ibk-bliss-mileage` | 배달앱(배민·쿠팡이츠) 1,500원당 2마일 — '온라인' 영역 소속이라 capGroup `on` |
| `shinhan-the-classic-neo` | Brunch 할인(평일 11~14시 요식업종 5%·월 2만원) |

요율이 수단별로 달라 한 줄로 뭉개져 있던 것도 갈렸다 —
`samsung-id-select-on`·`kb-you-wish`·`kb-my-wesh` 모두 **배달앱 5% / 음식점 10%** 로 요율이 다르다.

## 넣지 않기로 한 것

- `tossbank-check` 배달앱 5% — 온라인/오프라인 **모드가 완전 배타**인데 한도가 5,000 vs 2,000으로 달라
  capGroup으로 묶어 막을 수도 없다(스키마가 동일 cap을 요구). 넣으면 두 모드를 동시에 받는 계산이 된다.
- `bc-baro-onoff` 배달앱 — 공식 원문이 "국내 온라인 가맹점"이라고만 하고 배달앱을 명시하지 않아 §0(추정 금지).
- `hana-wonder-daily` 하나Pay 맛집 10% — 한정 가맹점이라 일반 외식 지출로 계산하면 과대평가라는 이전 라운드
  판단을 유지했고, 딜리버리 영역과 동시 선택이 가능한지도 원문으로 확정하지 못했다.

## 한도 처리

- 둘 다 대상이고 **한 한도를 나눠 쓰면** 줄 복제 + 같은 capGroup (10장). 새로 만든 그룹은 `shinhan-point-plan-plus` 하나
  (주말 음식점·배달앱이 **월 5회 통합 횟수**를 공유 — 검산: 5회 × 1,000P = 5,000P).
- **영역별 개별 한도**면 안 묶는다 (3장, 위의 되찾은 혜택들).
- 회귀 테스트(`src/data/cards.test.ts`)를 대중교통/택시와 배달앱/외식 양쪽에 돌도록 확장했다.
  실제로 `ibk-bliss-mileage`를 잡아냈는데, 확인해 보니 외식은 자체 한도·배달앱은 '온라인' 영역 한도라
  값만 같고 영역이 다른 정상 사례여서 예외 목록에 근거와 함께 넣었다.

통합한도 초과 0건. 추천 결과도 갈렸다 — 배달앱 1~2위는 KB NEED Pay·신한 Deep On Platinum+,
외식 1~2위는 KB NEED Pay·신한 처음으로 서로 다른 카드가 올라온다.
