# 포인트 종류·사용 난이도 조사 브리프 (2026-08-19)

너는 한국 신용/체크카드 38장에 대해 **"이 카드가 쌓아주는 포인트가 무엇이고, 얼마나 쉽게 쓸 수 있는지"**만 조사하는 조사원이다. 혜택률·연회비 같은 다른 값은 건드리지 않는다. 서브에이전트를 만들지 말고 직접 처리하라.

## 입력
`targets-X.json`: `{id, name, issuer, officialUrl, pointsRows}` 배열. pointsRows는 이 카드에서 포인트로 적립되는 혜택 요약.

## 도구 (카드 1장당 WebSearch 3회 안에서)
1. `officialUrl` WebFetch → 안 읽히면 WebSearch "<카드명> 포인트 적립 사용" → 카드사 공식(포인트 안내 페이지 포함) 우선, 안 되면 뱅크샐러드·카드고릴라(`https://api.card-gorilla.com:8080/v1/cards/{idx}` 텍스트도 됨).
2. 카드사 공통 포인트(마이신한포인트·KB 포인트리·하나머니·NH채움포인트·삼성 보너스포인트·BC TOP포인트·현대 M포인트·L.POINT)는 카드사 포인트 안내 페이지 한 번만 확인해서 같은 카드사 카드에 같이 적용해도 된다. 단 제휴 포인트(네이버페이·쿠팡캐시·스타벅스 별·코스트코 리워드·이마트 e포인트·신세계포인트·하나머니 트래블로그 등)는 카드별로 확인.

## 정할 것 (카드마다)
- `pointsProgram`: 사용자에게 보여줄 포인트 이름. 짧게. 예: "마이신한포인트", "M포인트", "네이버페이 포인트", "스타벅스 별", "쿠팡캐시", "포인트리", "하나머니", "NH채움포인트", "보너스포인트", "TOP포인트", "L.POINT", "코스트코 리워드"
- `pointsEase`: 셋 중 하나
  - `"cash"` — 현금처럼 쓰기 쉬움: 계좌 입금, 카드 결제대금 차감, 자동 캐시백 설정, 페이머니 전환 1:1 중 하나라도 되면. (마이신한포인트·포인트리·하나머니·NH채움포인트·보너스포인트·TOP포인트·네이버페이 포인트는 보통 여기. 단 실제로 확인해서 적어라.)
  - `"shop"` — 써야 함: 특정 가맹점·몰에서 쓰거나, 현금 전환이 되긴 하지만 손해(예: M포인트 1.5:1)인 경우. (M포인트·L.POINT 등)
  - `"limited"` — 특정 곳에서만: 한 브랜드/서비스 안에서만 쓰는 포인트 (스타벅스 별·쿠팡캐시·코스트코 리워드·이마트 e포인트·신세계포인트·트래블로그 해외결제 전용 등)
- `pointsNote`: 사용자에게 보일 한 줄(20자 안팎). 예: "계좌 입금·결제대금 차감 가능", "M포인트몰·가맹점에서 사용, 현금 전환 1.5:1", "스타벅스 앱에서 음료로 교환". 내부 문구("확인 필요", "출처") 금지.
- 확인 실패면 pointsEase는 넣지 말고 memoAppend에 "포인트 사용법 미확인: 사유".

## 출력: 지정된 `corrections-X.json`에 패치 배열만 (JSON, 주석 없음)
```json
[
  { "id": "shinhan-point-plan-plus", "set": { "pointsProgram": "마이신한포인트", "pointsEase": "cash", "pointsNote": "계좌 입금·결제대금 차감 가능" }, "memoAppend": "포인트 조사(2026-08-19): 신한카드 포인트 안내 페이지 확인" },
  { "id": "xxx", "memoAppend": "포인트 조사(2026-08-19): 포인트 사용법 미확인 — 공식 페이지 안 읽힘, 참고 사이트에도 없음" }
]
```
- 카드 1장 = 패치 1개, 38장 전부. 다른 필드는 절대 set 하지 마라.
- 파일에 쓰기 전 JSON 유효성 확인.
