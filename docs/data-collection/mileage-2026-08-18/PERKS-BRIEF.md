# 마일리지 카드 연간 보너스·프리미엄 혜택 채우기 브리프 (2026-08-18)

카드피커 마일리지 트랙에 두 필드가 새로 생겼다. 지정된 마일리지 카드들에 이 두 값을 공식 정보로 채우고, 값이 틀린 것이 보이면 함께 고쳐라(검증 브리프 `MILEAGE-BRIEF.md`의 규칙 그대로).

## 새 필드 (카드 최상위, 둘 다 선택)
```json
"mileageBonus": { "miles": 30000, "minAnnualSpend": 36000000, "firstYearMinSpend": 1000000 },
"perks": ["전 세계 공항 라운지 무제한(PP)", "대한항공 직판 항공권 할인 쿠폰 연 4장", "인천공항·특급호텔 발레파킹 월 10회"]
```
- `mileageBonus`: **연 1회 주는 보너스 마일**. `miles` = 마일 수(정수), `minAnnualSpend` = 2차년도 이후 조건인 **전년도 연 이용액(원)**(조건 없이 매년 주면 0), `firstYearMinSpend` = 첫해 조건(누적 이용액 원, 없으면 키 생략). 예: 대한항공카드 the First Edition2 = 3만 마일, 첫해 누적 100만 원, 이후 전년 3,600만 원. "탑승 시 보너스", "발급 이벤트 마일"은 넣지 않는다(상시·연간만). 분기·월 단위 정기 보너스는 **연 합계**로 환산해 넣고(예: 분기 1,500마일 → 6,000, 조건은 연 이용액으로 환산) memo에 원래 조건을 적어라. 없으면 키를 넣지 마라.
- `perks`: 사용자에게 그대로 보이는 부가 혜택 **최대 6줄**, 한 줄에 하나, 짧고 구체적으로(라운지 횟수, 바우처 금액·장수, 발레파킹 횟수, 호텔·골프, 항공권 할인 쿠폰 등). 12개 태그 안에 들어가는 적립/할인은 여기 적지 말 것. 조건(전월실적 등)이 있으면 괄호로. 내부 문구("확인 필요", "출처") 금지. 없으면 키를 넣지 마라(빈 배열 금지). 연회비 10만 원 미만 카드는 라운지 등이 있으면만 1~2줄.

- `mileConversion`(선택, 문자열): 포인트→마일 전환형 카드에만. 사용자에게 보이는 환산 기준 한 문장(예: "멤버십 리워즈 포인트(1,000원당 1MR)를 대한항공 스카이패스 마일로 1.5:1 전환한 값이에요"). 있으면 화면에 '포인트 전환형' 배지가 붙는다.

## 출력: 패치 배열 (`apply-corrections.mjs` 형식)
```json
[
  { "id": "hyundai-koreanair-060",
    "set": { "lastChecked": "2026-08-18", "mileageBonus": { "miles": 1000, "minAnnualSpend": 0 }, "perks": ["대한항공 직판 항공권 할인 쿠폰 연 1장(5만 원)"] },
    "memoAppend": " 보너스·부가혜택(2026-08-18): 공식 페이지 확인 — 연 1회 1,000마일(조건 없음), 항공권 쿠폰 1장. 라운지 없음." }
]
```
- 값이 틀린 게 보이면 `set`/`benefits`에 같이 넣어라(검증 브리프 형식). 못 찾으면 memoAppend에 "미확인: …".
- 신규 카드를 추가하는 배치는 카드 JSON 전체(BRIEF.md 형식)에 `mileageBonus`·`perks`를 포함해 `incoming/*.json`에 저장.
