# 카드픽(가제) — 성향 기반 카드 추천 사이트 설계

작성일: 2026-08-16
상태: 사용자 승인 (브레인스토밍 완료)

## 1. 목적

"내 성향 + 관심 혜택 + 월 사용액 + 연회비 허용치"를 넣으면 **범용성 기준으로 정답에 가까운 카드 몇 장**을 골라주는 공개 웹사이트.

- 카드고릴라·뱅크샐러드처럼 수천 장을 나열하는 게 아니라 **골라주는 것**이 목적.
- 사용자는 클릭 몇 번 + 숫자 두 개만 입력. 정밀 입력(영역별 금액 등)은 의도적으로 하지 않는다 — 단순함이 제품의 핵심.
- 사람마다 정답이 다르다는 걸 **성향(카드 혜택을 얼마나 꼼꼼히 챙기며 사는지)**으로 푼다.

## 2. 범위

### 포함
- 국내 신용·체크카드. 데이터는 넓게(수백 장) 모으고 조건으로 걸러낸다.
- 카드의 **기본 혜택 구조**만 다룬다 (연회비, 전월 실적, 태그별 혜택·한도).
- 12개 태그로만 분류. 그 밖의 혜택은 메모로만 보관.

### 제외 (첫 버전)
- 이벤트성·기간 한정 혜택
- 로그인, 사용자 데이터 저장, 방문 추적
- 관리 화면 (데이터 편집은 Claude Code 세션에서)
- 서버·DB
- 수익화

## 3. 만드는 방식

- **서버 없는 정적 사이트.** 화면 코드 + `cards.json` 하나. 추천 계산은 방문자 브라우저 안에서 실행.
- 스택: TypeScript, React + Vite, Vitest. (스케줄 앱과 동일해 두 프로젝트를 오가도 낯설지 않게.)
- 호스팅: GitHub + Vercel(또는 Cloudflare Pages). push하면 자동 배포, 무료 주소.
- 제보: 구글 폼 링크.
- 모바일 우선 레이아웃.

## 4. 화면 (3개)

### 화면 1 — 나에 대해
- **성향** (하나 선택, 각 한 줄 설명)
  - **꼼꼼형** — 실적·한도 다 따지고 결제 전에 어떤 카드 낼지 생각해요
  - **적당형** — 대충은 알고 쓰지만 매번 계산하진 않아요
  - **무심형** — 한 장 꽂아두고 신경 끄고 싶어요
- **월 카드 사용액** (숫자, 만 원 단위)
- **연회비 허용치** (슬라이더, 0 ~ 20만 원, 맨 끝은 "상관없음")
- [다음 →]

### 화면 2 — 관심 있는 혜택
- 태그 12개 버튼, 다중 선택 (최소 1개)
- 4개째 선택부터 버튼 아래에 작은 빨간 안내 문구: *"많이 고르면 추천이 흐려져요. 2~3개가 딱 좋아요."* — 팝업 없음, 선택 제한 없음
- [← 이전] [추천 받기]

### 화면 3 — 결과
- 조건에 맞는 카드 **TOP 5**
- 카드마다: 이름, 카드사, 신용/체크, 연회비, 전월 실적, **"왜" 한두 줄**, 혜택 요약(펼치기), 공식 페이지 링크, **마지막 확인일** (90일 초과 시 "확인 필요" 뱃지)
- 성향별 표시 차이 → 6절 참조
- 조건에 맞는 카드가 없으면: 빈 결과 안내 + "조건 바꾸기"
- 하단: 조건 바꾸기 / 정보가 틀렸나요? 제보하기(구글 폼)

## 5. 데이터

### 5.1 태그 (12개, 고정)
`마일리지` · `모든 가맹점` · `주유` · `카페·편의점` · `온라인 쇼핑` · `배달·외식` · `대중교통·택시` · `통신비·OTT` · `병의원·약국` · `해외 결제` · `학원·교육` · `관리비·공과금`

### 5.2 카드 1장의 항목 (`cards.json`)
| 항목 | 설명 |
|---|---|
| id | 고유 문자열 |
| name | 카드 이름 |
| issuer | 카드사 |
| kind | `credit` / `check` |
| annualFee | 연회비 (원). 여러 브랜드면 가장 낮은 값 |
| minSpend | 전월 실적 (원). 없으면 0 |
| benefits[] | 태그별 혜택 목록. 각 항목: `tag`, `type`(`discount`/`points`/`mileage`), `rate`(%), `monthlyCap`(원, 없으면 null), `stars`(1~3), `note` |
| universal | 범용 적립·할인 (있으면): `type`, `rate`, `monthlyCap` |
| complexity | 1~3. 1=조건 단순, 2=영역 혜택 2~3개, 3=선택형 팩·제외 항목 많음 |
| officialUrl | 공식 페이지 주소 (변경 감지에도 사용) |
| lastChecked | 마지막 확인일 (YYYY-MM-DD) |
| status | `active` / `discontinued` |
| memo | 검수 메모, 12개 태그 밖의 혜택 등 |

### 5.3 등급·복잡도 기준
- ★등급과 복잡도는 AI가 페이지를 읽고 1차로 매기고, 검수 때 조정한다.
- 기준(예: 할인율·한도가 얼마 이상이면 ★3)은 `rules` 파일 하나에 적어두고 거기서만 바꾼다.

## 6. 추천 계산

순서대로 적용한다.

### 6.1 성향으로 풀 나누기
- 무심형: `complexity === 3` 제외
- 적당형·꼼꼼형: 전부

### 6.2 걸러내기 (제외)
- `status !== active`
- 연회비 > 허용치 (허용치 "상관없음"이면 통과)
- 월 사용액 < `minSpend`
- 고른 태그 중 하나도 `benefits`/`universal`에 없음

### 6.3 점수
- 고른 태그 커버 수 — 가장 큰 비중 (범용성)
- 커버한 태그의 ★ 합
- 연회비 낮을수록 가산
- 실적 낮을수록 가산

### 6.4 성향 보정
"범용 카드" = `universal`이 있고 `complexity === 1`. "영역별 카드" = 그 외.

| 성향 | 범용 카드 | 영역별 카드 |
|---|---|---|
| 꼼꼼형 | 보통 | **앞으로** (가산) |
| 적당형 | **앞으로** (가산) | 뒤로 (감점, 목록엔 유지) |
| 무심형 | **맨 앞** (큰 가산) | 맨 뒤 (큰 감점) |

### 6.5 결과 표시
- **적당형·무심형**: ★등급 + 조건 한 줄. 예) "고른 3개 중 2개 커버 · 주유 ★★★ · 연회비 1.3만 · 실적 30만"
- **꼼꼼형**: 위에 더해 **영역별 월 최대 혜택 표**
  - 태그별: 비율 → 월 최대 혜택액(= `monthlyCap`, 없으면 "한도 없음")
  - 합계: "다 챙기면 월 최대 ○원 · 연 최대 ○원 – 연회비 = 약 ○원"
  - 한도 채우는 데 필요한 지출: `monthlyCap ÷ rate`로 역산해 "한도를 다 채우려면 주유 15만·카페 10만 이상 써야 해요"
  - "최대"임을 명확히 표기 (실제 이득이 아니라 상한)

### 6.6 조정 가능성
- 점수 비중, 가산·감점 수치는 첫 버전 임시값. `rules` 파일 한 곳에 모아 두고 실제 카드를 넣어보며 조정한다.

## 7. 데이터 수집·유지보수

### 7.1 처음 채우기
1. Claude Code 세션에서 카드사별 카드 목록을 훑어 카드 페이지 주소를 모은다.
2. 카드마다 페이지를 읽어(WebFetch) 5.2 항목으로 정리 → `cards.json`에 추가.
3. 읽히는 곳/안 읽히는 곳 (2026-08-16 시험):
   - 잘 읽힘: 신한카드 공식, KB국민카드 공식(모바일 페이지)
   - 절반: 삼성카드 공식 (세부 수치는 접힌 부분)
   - 안 읽힘: 현대카드 공식, 카드고릴라 (자바스크립트 렌더링)
   - 정리 사이트 뱅크샐러드는 잘 읽힘 → **참고용으로만**. 원칙은 "공식 페이지 우선, 안 될 때만 정리 사이트 참고 후 사용자 확인". 정리 사이트 데이터를 그대로 서비스에 싣지 않는다.
4. 사용자 검수: 처음엔 **성향별 상위 20장 정도**만 꼼꼼히 확인 (화면에 뜨는 카드가 그것). 나머지는 AI 값 그대로 두되 `lastChecked`로 구분.

### 7.2 유지보수
- 월 1회 예약 실행: 저장된 `officialUrl`을 다시 읽어 달라진 카드 목록 → 사용자에게 알림.
- 사용자가 세션을 열어 갱신 → 검수 → push → 자동 배포.
- 90일 넘게 확인 안 한 카드는 화면에 "확인 필요" 뱃지 (자동).
- 구글 폼 제보도 세션에서 처리.
- 카드 단종·개악은 실제로 자주 일어나므로 "새 카드 나올 때만"이 아니라 기존 카드 변경 감지가 핵심.

## 8. 테스트

- 추천 계산(6절)은 순수 함수로 두고 Vitest로 규칙을 고정한다. 예:
  - 무심형이면 복잡도 3 카드가 결과에 없다
  - 연회비 허용치 초과 카드는 빠진다
  - 월 사용액이 실적 미만이면 빠진다
  - 고른 태그를 더 많이 커버하는 카드가 위에 온다
  - 무심형은 범용 카드가 영역별 카드보다 위에 온다
  - 꼼꼼형 결과에는 영역별 월 최대 혜택 표가 붙는다
- `cards.json` 형식 검증 테스트: 태그는 12개 중 하나, 복잡도·★는 1~3, 날짜 형식 등.
