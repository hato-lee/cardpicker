# 카드피커 — "연 최대 혜택" 개편 설계 (2026-08-18)

기존 설계(`2026-08-16-cardpick-design.md`)의 **추천 점수·결과 화면** 부분을 대체한다. 데이터 층(cards.json, 스키마, 태그 12개), 입력 흐름(화면 1·2)은 유지한다.

## 왜 바꾸나
사용자가 결과에서 보고 싶은 건 "이 카드로 **1년에 얼마** 이득인가"다. 지금 화면은 내부 점수 근거(★, 커버 수)만 보여줘서 "그래서 얼마?"가 없다.
사용자 결정: 한 달 사용액을 태그별로 나누지 않는다(추정 위 추정 금지). 대신 대부분 혜택엔 **월 한도**가 있으니 한도를 그대로 "최대"로 쓴다.

## 계산: 카드 1장의 연 최대 혜택 (`annualBenefit`)

입력: 카드, Query(성향, 한 달 사용액 S, 연회비 허용치, 고른 태그들), RULES.

### 1. 줄(row) 만들기 — 고른 태그마다 하나, 범용은 한 번
- 고른 태그 t에 카드 benefits 항목 b가 있으면 **영역 줄**:
  - `type mileage`: 월 마일 = `min(cap, S × rate/100)` (cap null이면 `S × rate/100`) → 원 = 마일 × `RULES.mileWon`(15원). requiredSpend = cap 있으면 `cap/(rate/100)`, 없으면 S.
  - `rate > 0`, cap 있음: 월 혜택 = cap. requiredSpend = `cap/(rate/100)`.
  - `rate > 0`, cap 없음: 월 혜택 = `S × rate/100`. requiredSpend = S. (총액 기준 상한 — 태그별 나누기 없음)
  - `rate = 0`(정액·수수료 면제): 월 혜택 = cap ?? 0. requiredSpend = null (아래 상한 조정에서 제외).
- 고른 태그 중 benefits에 없는 태그가 하나라도 있고 `card.universal`이 있으면 **범용 줄** 한 번(고른 태그 수와 무관): 월 혜택 = `min(cap, S × rate/100)` (mileage면 마일→원 환산), requiredSpend = `min(S, cap/(rate/100))`. '모든 가맹점'을 직접 골랐으면 그 영역 줄이 곧 범용 줄이므로 중복으로 넣지 않는다.
- 중복 방지: '마일리지' 줄과 '모든 가맹점' 줄이 둘 다 `type mileage`이면(전 가맹점 마일리지 카드) 같은 적립을 두 번 세는 것이므로 **'마일리지' 줄만** 남긴다.
- 어떤 줄도 없으면 카드는 후보에서 제외(기존 필터와 동일).

### 2. 현실성 상한 (총액으로만)
`R = Σ requiredSpend`(null 제외). `R > S`이면 `factor = S / R`을 rate 기반 줄들의 월 혜택에 곱한다. 정액 줄은 그대로. (월 30만 원 쓰는 사람이 5개 한도 10만 원을 다 채울 순 없다 — 이것만 막는다.)

### 3. 합계
- `monthlyMax = Σ 줄.월혜택` (상한 조정 후)
- `annualGross = monthlyMax × 12`
- `annualRealized = annualGross × RULES.personaRealization[persona]` — 꼼꼼 1.0 / 적당 0.8 / 무심 0.6
- `annualNet = round(annualRealized − annualFee)` ← **정렬 기준이자 화면의 큰 숫자**

### 4. 후보 필터 (기존 유지)
status active · 무심형은 complexity ≤ 2 · annualFee ≤ feeLimit(null이면 무제한) · minSpend ≤ S · 줄이 1개 이상.

### 5. 정렬
annualNet 내림차순 → 동률이면 연회비 낮은 순 → 실적 낮은 순. 상위 `topN`(5). annualNet이 0 이하인 카드도 순위에 남기되 화면에 "연회비가 혜택보다 커요"로 표시.

기존 `weight`·`personaMultiplier`·★ 기반 점수는 삭제한다. ★·complexity는 데이터에 남기고(무심형 필터·수집 기준용) 화면에서는 ★를 쓰지 않는다.

## 설명 (`explain`)
- **breakdown**: 줄마다 `{ tag, type, rate, monthlyValue(상한 조정 후, 성향 반영 전), requiredSpend, capped, viaUniversal }`. 화면의 "온라인쇼핑 9만 · 교통 6만" 내역과 미니 막대에 쓴다 (금액은 연 = 월×12×성향비율로 표기).
- **tips** ("이렇게 쓰면 최대"): 줄마다 한 문장.
  - cap 있고 rate>0: `"{tag}에 월 {won(requiredSpend)} 이상 쓰면 한도({won(cap)})를 꽉 채워요"`
  - cap 없음: `"{tag}는 쓰는 만큼 {rateText} — 한도 없음"`
  - 정액: `"{tag}: {note 앞부분}"` (note 없으면 "정액 혜택")
  - 범용 줄: `"그 외 소비는 모든 가맹점 {rateText}"`
  - 성향별 개수: 꼼꼼형 전부 / 적당형 상위 2개(월 혜택 큰 순) / 무심형 상위 1개, 무심형 문구 앞에 "이것만 챙기세요:" 접두.
- 기존 `reasonLine`, `maxBenefitTable`(꼼꼼형 표)은 삭제한다 — breakdown이 모든 성향에서 대체.

## 결과 화면
```
┌ 내 조건: [적당형] [월 50만] [연회비 3만까지] [온라인 쇼핑] [대중교통·택시]   조건 바꾸기 ┐
당신에게 맞는 카드 TOP 5
┌─────────────────────────────────────────────┐  ← 1위: 파란 테두리 + "추천" 배지
│ ① BC 바로 클리어 플러스           연 최대     │
│ BC카드 · 신용 · 연회비 5천 원 · 실적 15만   약 18.4만 원│  ← 큰 숫자(강조색)
│ 연회비 뺀 금액 · 적당형 기준(한도의 80%)      │  ← 작은 회색
│ 온라인 쇼핑 ▇▇▇▇▇ 9.6만  대중교통·택시 ▇▇▇ 8.8만 │  ← 내역+미니 막대
│ 자세히 보기 ▼                                 │
│   이렇게 쓰면 최대: · 온라인 쇼핑에 월 20만 원 이상 … │
│   전체 혜택: · 배달·외식 7% 할인 · 월 최대 2만 원 (…) │  ← memo는 안 보여줌
│ 카드사 페이지 →                마지막 확인 2026-08-18 │
└─────────────────────────────────────────────┘
```
- 큰 숫자: `약 {won(annualNet)}` (annualNet>0). 0 이하: `연회비가 혜택보다 커요 (−{won(|net|)})` 회색·작게.
- "연 최대"라는 말은 항상 붙인다(한도 기준임을 명시). 부제: `연회비 {won} 뺀 금액 · {성향명} 기준(한도의 {%})`.
- 내역 줄: 줄이 3개 초과면 상위 3개 + "외 N개". 막대 길이 = 그 줄 연 금액 / 카드 내 최대 줄.
- 펼치기 안에 tips → 전체 benefits 목록. `memo`는 화면에 표시하지 않는다.
- ★, "고른 N개 중 M개 커버", 꼼꼼형 전용 표는 삭제.
- 빈 결과·제보 링크·stale 배지 동작은 기존 유지.

## 입력 화면 (문구·편의만)
- 성향 설명 끝에 반영 방식 추가: 꼼꼼형 "→ 한도를 다 챙긴다고 계산해요", 적당형 "→ 한도의 80%로 계산해요", 무심형 "→ 한도의 60%로 계산해요".
- 한 달 사용액: 입력칸 위에 빠른 선택 버튼 `30 · 50 · 100 · 150`(만 원, `RULES.spendPresetsMan`). 누르면 입력칸에 채워짐. 직접 입력도 그대로.
- 연회비 슬라이더 아래 힌트: "이 금액을 넘는 카드는 안 보여줘요. 결과의 연 혜택은 연회비를 이미 뺀 금액이에요."
- 태그 주의 문구(4개부터): "많이 고를수록 한도 합이 커져서 조건 많은 카드가 위로 와요. 2~3개가 딱 좋아요."

## RULES (rules.ts)
```ts
export const RULES = {
  topN: 5,
  staleDays: 90,
  personaRealization: { meticulous: 1.0, moderate: 0.8, carefree: 0.6 },
  mileWon: 15,                    // 1마일 ≈ 15원
  carefreeMaxComplexity: 2,
  tipCount: { meticulous: Infinity, moderate: 2, carefree: 1 },
  spendPresetsMan: [30, 50, 100, 150],
  breakdownMaxRows: 3,
}
```
`STAR_GUIDE`는 수집 기준으로 유지.

## 테스트 (핵심 케이스)
- 한도 있는 할인: 월 혜택 = cap, requiredSpend = cap/rate.
- 한도 없는 정률: S × rate.
- 마일리지: 마일 × 15원, cap은 마일 단위.
- 정액(rate 0): cap 그대로, 상한 조정 안 받음.
- 상한: R > S이면 비례 축소, R ≤ S이면 그대로.
- 범용: 미커버 태그가 여러 개여도 한 번만; '모든 가맹점' 직접 고르면 중복 없음.
- 성향 비율·연회비 차감·정렬(annualNet → fee → minSpend)·topN.
- tips 개수/문구(성향별), UI: 큰 숫자·부제·내역·1위 배지·memo 미표시·프리셋 버튼·문구.

## 범위 밖
태그별 지출 입력, 실적 구간별 한도, 마일 가치 사용자 조정, 데이터 변경.
